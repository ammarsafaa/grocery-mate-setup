# خطة: تشغيل كاشير ثانٍ مع SQL Server داخل المحل

## الفكرة
- جهاز واحد في المحل يكون **الخادم الرئيسي** وعليه SQL Server Express (مجاني).
- كل كاشير (الأول والثاني وأكثر) يبقى عنده قاعدة بياناته المحلية الحالية، فيبيع بسرعة حتى لو انقطعت الشبكة.
- البرنامج يرسل المبيعات وحركات المخزون إلى الخادم تلقائياً كل بضع ثوانٍ، ويستقبل منه المنتجات والأسعار والمستخدمين.
- إذا انقطع الاتصال: الكاشير يكمل البيع، والبيانات تنتظر ثم تُرسل عند رجوع الشبكة.

## ماذا سيظهر في الإعدادات
- قسم جديد «الربط مع الخادم (SQL Server)»: تشغيل/إيقاف، عنوان الخادم، اسم القاعدة، اسم المستخدم وكلمة السر، اسم هذا الكاشير (مثلاً كاشير 1، كاشير 2).
- زر «اختبار الاتصال» وزر «مزامنة الآن».
- مؤشر صغير في نقطة البيع: متصل / غير متصل / عدد العمليات المنتظرة.

## قواعد مهمة
- تعديل السعر أو المنتج من أي جهاز يصل لكل الأجهزة.
- المخزون يُحسب من مجموع مبيعات كل الكاشيرات، فلا يختلف بين الأجهزة.
- أرقام الفواتير تحمل رمز الكاشير (مثل 1-105 و 2-87) حتى لا تتكرر.
- التقارير في أي جهاز يمكنها عرض مبيعات كل الكاشيرات أو كاشير واحد.
- كل كاشير يحتاج ترخيصاً خاصاً بجهازه (كما هو الآن).
- إذا لم يُفعَّل الربط، يعمل البرنامج تماماً كما هو اليوم.

## ما يحتاجه العميل
- راوتر يربط الأجهزة، وتثبيت SQL Server Express على جهاز الخادم (سأكتب لك خطوات تثبيت بسيطة بالعربي).

## حدود الاختبار بصراحة
- لا أستطيع تشغيل SQL Server أو أجهزة Windows هنا؛ سأفحص الكود والبناء فقط، والتجربة الحقيقية تكون على جهازين في المحل.

## تفاصيل تقنية
- مكتبة `mssql` (tedious، JavaScript خالص) داخل عملية Electron الرئيسية، عبر IPC من الواجهة.
- جدول outbox محلي في SQLite لكل تغيير، مع معرّفات UUID ورمز الجهاز؛ إرسال دوري وإعادة محاولة.
- جداول على الخادم: products, groups, users, sales, stock_movements, shifts, expenses, purchases, suppliers مع عمود updated_at؛ السحب حسب آخر تحديث (آخر تعديل يفوز للمنتجات والأسعار، والمبيعات والحركات إضافة فقط).
- إنشاء الجداول تلقائياً عند أول اتصال.
