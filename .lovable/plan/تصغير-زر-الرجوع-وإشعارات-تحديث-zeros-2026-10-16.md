# تصغير زر الرجوع وإشعارات تحديث Zeros

## التغييرات
- يصبح «رجوع» زرّاً صغيراً فوق شبكة المنتجات، بدلاً من مربع بحجم المنتج، مع السهم واللون الكهرماني والنص الداكن.
- يفحص برنامج Windows توفر نسخة أحدث عند التشغيل ثم دورياً عند وجود إنترنت، ويعرض إشعاراً غير مزعج برقم النسخة وزر التنزيل.
- التنزيل والتثبيت باختيار المستخدم؛ لا يُغلق البرنامج أثناء البيع ولا يُثبَّت التحديث قبل إغلاق الوردية. البيانات المحلية تبقى محفوظة، مع نسخة احتياطية قبل التثبيت.
- يبقى زر فحص التحديث يدوياً في الإعدادات. عدم وجود إنترنت لا يمنع البيع.

## مستودع GitHub الخاص
- يبقى المستودع خاصاً، وتُجلب ملفات التحديث عبر خدمة آمنة في Lovable Cloud.
- يُحفظ اسم الحساب والمستودع ورمز وصول محدود بقراءة محتويات المستودع في الخدمة الآمنة؛ لا يُوزّع رمز المالك داخل EXE أو واجهة الإعدادات.
- بعد الموافقة نفعّل Cloud، نتحقق من اتصال GitHub المتاح، ثم نطلب التوكن بنموذج آمن إذا احتجناه. لا ترسله في المحادثة.
- إشعار التحديث يظهر فقط بعد نجاح إنشاء ونشر إصدار Windows برقم أحدث، وليس عند كل تعديل على الموقع.
- الوصول إلى تنزيلات العملاء يُحمى برمز تنزيل منفصل محدود، لا يمنح أي صلاحية على GitHub. لا يكفي معرّف الجهاز وحده لإثبات الترخيص.

## تفاصيل تقنية
- الاستفادة من electron-updater الموجود، مع مصدر تحديث generic وخدمة تجلب latest.yml وملفات EXE وblockmap من GitHub دون كشف PAT أو تمريره في روابط العميل.
- تنزيل الملفات يُمرر بالتدفق أو عبر رابط تنزيل مؤقت صادر من GitHub؛ لا يُخزن الملف كاملاً في ذاكرة الخدمة، ولا يُرسل التوكن إلى وجهة إعادة توجيه.
- التحقق من مسارات وأسماء الملفات وحصر المصدر بالمستودع المحدد، مع حدود طلبات ورسائل خطأ عربية واضحة.
- اختبار زر الرجوع وإشعارات الحالات في المعاينة. التحقق من التنزيل والتثبيت الفعلي يحتاج إصداراً منشوراً وتجربة على Windows؛ لا يمكن إنتاج EXE داخل هذه البيئة.

## الموافقة المطلوبة
الموافقة على تصغير زر الرجوع وعلى استخدام Lovable Cloud لحماية توكن المستودع الخاص وإتاحة التحديثات للعملاء.
